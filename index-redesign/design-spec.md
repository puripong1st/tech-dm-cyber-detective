# Design specification: หน้าแรก Cyber Shield Detective ฉบับคลีนและ SEO-first

## ภาพรวมโครงการ

ออกแบบต้นแบบหน้าแรกใหม่สำหรับเว็บไซต์ “Cyber Shield Detective” ซึ่งเป็นศูนย์รวมเกมและสื่อการเรียนรู้เรื่อง พ.ร.บ.คอมพิวเตอร์ พ.ศ. 2560 และ PDPA สำหรับนักเรียนระดับมัธยมศึกษาปีที่ 3 และครูผู้สอน ปัญหาของหน้าเดิมไม่ใช่การขาดเนื้อหา แต่เป็นการใส่ทุกอย่างไว้ในระดับความสำคัญใกล้เคียงกัน หน้าเดียวมีลิงก์ประมาณ 58 จุด หัวข้อ H1–H3 ประมาณ 36 หัวข้อ หมวดระบบ 7 หมวด ตารางเอกสาร 12 ระบบ สรุปมาตรากฎหมาย 12 รายการ และ FAQ หลายข้อ ทำให้ผู้ใช้ต้องอ่านและตัดสินใจมากเกินไปก่อนจะเริ่มเรียนหรือเริ่มสอน การออกแบบใหม่ต้อง “คลีน” ในความหมายของลำดับที่ชัด ไม่ใช่เพียงเปลี่ยนเป็นพื้นขาว และต้องรักษาเนื้อหาที่เป็นประโยชน์ต่อการค้นหาโดยไม่ทำหน้าแรกให้กลับมาหนักอีก

## กลุ่มเป้าหมายและสถานการณ์ใช้งาน

กลุ่มหลักมีสองกลุ่ม กลุ่มแรกคือนักเรียน ม.3 ที่เข้าผ่านมือถือหรือคอมพิวเตอร์ในห้องเรียน ต้องการเริ่มเกมหรือกิจกรรมได้เร็ว อ่านภาษาไทยได้ง่าย และไม่ต้องเข้าใจชื่อระบบทั้งหมดก่อนเริ่ม กลุ่มที่สองคือครูผู้สอนที่ต้องการเลือกสไลด์ เกม ใบงาน คลังคดี หรือศูนย์ควบคุมให้เหมาะกับเวลาเรียน ครูควรมองเห็น “เส้นทางสอน” ที่เป็นขั้นตอนแทนการเจอแค็ตตาล็อกยาว กลุ่มรองคือผู้ปกครอง ผู้พัฒนาสื่อ และผู้ค้นหาความรู้เกี่ยวกับ พ.ร.บ.คอมพิวเตอร์/PDPA ผ่าน Google ซึ่งต้องเห็นคำอธิบายเว็บไซต์ ผู้จัดทำ ขอบเขตเนื้อหา และแหล่งอ้างอิงที่ชัดเจน

## เป้าหมายประสบการณ์

ภายใน 5 วินาที ผู้ใช้ต้องตอบได้ว่าเว็บไซต์นี้สอนอะไร เหมาะกับใคร และควรกดตรงไหน การกระทำหลักเหนือรอยพับมีเพียง 2 ทาง ได้แก่ “เริ่มเรียน/เล่น” และ “วางแผนการสอน” โดยลิงก์หลักของนักเรียนควรนำไปเกม Cyber Shield Detective เวอร์ชัน 6 คดี ส่วนเส้นทางครูควรเลื่อนไปยังชุดแนะนำการสอนบนหน้าเดียวกัน ไม่วางแดชบอร์ดครูที่ถูก robots.txt บล็อกเป็นหน้าหลักเพื่อ SEO หลัง hero ให้มีเครื่องมือแนะนำ 4 รายการเท่านั้น: เกมหลัก 6 คดี, สไลด์ พ.ร.บ.คอมพิวเตอร์, สไลด์ PDPA 101 และกระดานใบงาน PDPA เครื่องมืออื่นรวมไว้ใน “ดูเครื่องมือทั้งหมด” แบบรายการที่สแกนง่าย ไม่ทำการ์ดใหญ่ทุกลิงก์

## สถาปัตยกรรมเนื้อหาที่ต้องมี

1. Header สั้น: โลโก้/ชื่อเว็บไซต์ ลิงก์ “สำหรับนักเรียน”, “สำหรับครู”, “ความรู้กฎหมาย” และปุ่มเริ่มกิจกรรม ไม่ใส่ GitHub หรือเอกสารทางเทคนิคในเมนูหลัก
2. Hero: H1 เดียวที่บอกสาระหลัก เช่น “เรียนรู้กฎหมายไซเบอร์ ผ่านคดีที่ได้ลงมือคิด” คำอธิบายหนึ่งย่อหน้าที่มีคำค้นตามธรรมชาติ “เกม พ.ร.บ.คอมพิวเตอร์ 2560 และ PDPA สำหรับนักเรียน ม.3” CTA สองปุ่ม และสัญญาณความน่าเชื่อถือสั้น ๆ ว่าใช้ได้ฟรีบนเว็บ/เหมาะกับชั้นเรียน โดยห้ามสร้างตัวเลขผู้ใช้หรือคำรับรองที่ไม่มีหลักฐาน
3. ทางเลือกตามบทบาท: แยก “ฉันเป็นนักเรียน” กับ “ฉันเป็นครู” แบบโมดูลใหญ่ 2 รายการหรือโครงสร้างอื่นที่ชัดเจน แต่ต้องไม่ซ้ำ CTA hero ทั้งหมด
4. เครื่องมือแนะนำ 4 รายการ พร้อมชื่อภาษาไทยที่เข้าใจทันที คำอธิบายสั้น 1–2 บรรทัด ป้ายระยะเวลา/รูปแบบเท่าที่มีข้อมูลจริง และลิงก์ HTML ที่มีอยู่จริง
5. เส้นทางสอน 3 ขั้น: ปูพื้นด้วยสไลด์ → วิเคราะห์คดีด้วยเกม → สร้างชิ้นงานด้วย PDPA Assignment Board เพื่อช่วยครูตัดสินใจและสร้าง internal links แบบมีความหมาย
6. เนื้อหาความรู้สำหรับ SEO: ย่อเป็น 2 บล็อก “พ.ร.บ.คอมพิวเตอร์คืออะไร” และ “PDPA เกี่ยวข้องกับนักเรียนอย่างไร” บล็อกละประมาณ 80–130 คำ พร้อมลิงก์ไปหน้าบทเรียนเฉพาะ ไม่ยกสรุป 12 มาตรามาวางเต็มหน้าแรก
7. FAQ ที่มองเห็นจริง 3 ข้อ เน้นคำถามที่ผู้ใช้ต้องรู้ก่อนเริ่ม เช่น ต่างกันอย่างไร, ใช้ในคาบเรียนอย่างไร, ต้องติดตั้งหรือไม่ สามารถใช้ details/summary ได้ แต่ schema FAQ ไม่ใช่สิ่งที่ต้องเน้นเพราะ Google จำกัด rich result สำหรับเว็บไซต์ประเภทนี้
8. ส่วนความน่าเชื่อถือ: ระบุผู้จัดทำ/ทีมโครงการอย่างถูกต้อง ช่องทางดูซอร์สบน GitHub และคำเตือนว่าเนื้อหาเป็นสื่อการเรียนรู้ ไม่ใช่คำปรึกษาทางกฎหมาย พร้อมพื้นที่สำหรับ “แหล่งอ้างอิงกฎหมาย” ในงานจริง
9. Footer สั้น: ลิงก์เครื่องมือทั้งหมด, เกี่ยวกับโครงการ, GitHub และสถานะเอกสาร ไม่แสดงตาราง README ในหน้าแรก

## SEO และข้อกำหนดเทคนิค

ต้นแบบต้องมี semantic HTML ที่สมเหตุผล: หนึ่ง H1, H2 ตามหมวด, H3 เฉพาะรายการย่อย, `main`, `nav`, `section`, `article`, `footer` และ anchor text ที่บอกปลายทาง ห้ามใช้ข้อความ “คลิกที่นี่” เป็นลิงก์หลัก ต้องมี title และ meta description ที่กระชับ, canonical เดิม, Open Graph, `WebSite` JSON-LD และ `ItemList` เฉพาะรายการที่มองเห็นได้จริง BreadcrumbList บน homepage ไม่จำเป็นและไม่ควรสร้าง breadcrumb ปลอมหลายระดับ หลีกเลี่ยง meta keywords และหลีกเลี่ยง FAQ schema ที่ไม่ได้สร้างคุณค่าจริง รูปภาพต้องมี width/height, alt ที่สื่อความหมาย, lazy-load เมื่ออยู่นอกจอ และไม่ใช้ favicon สี่เหลี่ยมเล็กเป็น `og:image` ในงานจริง—ควรสร้าง social image 1200×630 ภายหลัง

โค้ดแต่ละต้นแบบเป็น HTML เดียว เปิดจาก local server ได้ ไม่พึ่ง build step รองรับกว้าง 1280×720 เพื่อเทียบภาพ และต้องตอบสนองบน 390×844 ใช้ระบบฟอนต์ไทยที่อ่านง่าย เช่น Bai Jamjuree/Sarabun/IBM Plex Sans Thai หรือ system fallback ขนาด body desktop 16–18px แตะเป้าหมายไม่น้อยกว่า 44px มี focus-visible ที่ชัด รองรับ `prefers-reduced-motion` และไม่ใช้ animation ที่ขัดขวางการอ่าน หลีกเลี่ยงไลบรารีไอคอนภายนอก; ใช้ตัวอักษร สัญลักษณ์ CSS หรือ SVG เล็กที่สร้างในไฟล์ได้

## ทิศทางอารมณ์และข้อห้าม

คีย์เวิร์ดอารมณ์คือ เป็นมิตร, มีพลังแบบห้องเรียน, เชื่อถือได้, ชัดเจน, ไม่ทำให้กฎหมายดูน่ากลัว, ไม่ดูเหมือนแดชบอร์ดสำหรับผู้เชี่ยวชาญ ห้ามกลับไปใช้พื้นน้ำเงินเข้มพร้อม glow หลายสี, glass card เต็มหน้า, gradient ตัวอักษร, pill จำนวนมาก, การ์ดกลมทุกอย่าง, emoji เป็นภาพหลัก, metric ปลอม, คำโฆษณาเกินจริง หรือการยัดคำค้นซ้ำ ๆ ทุกส่วน สีต้องมาจากสินทรัพย์จริงและบริบท: น้ำเงินเข้ม/ฟ้าจากโลโก้ Cyber Shield, เหลืองอำพันจากบริบทสัญญาณเตือน, เขียวมิ้นต์จากไอคอน PDPA และนิวทรัลอุ่นเพื่อให้สายตาพัก แต่แต่ละ direction ต้องตีความต่างกันอย่างชัดเจน

## รูปภาพและ visual motif

หน้าแรกเป็น product hub จึงไม่จำเป็นต้องมีภาพถ่ายจากเว็บภายนอก ภาพที่มีความหมายคือโลโก้ `favicon.png`, ไอคอน `assets/pdpa_icon.png` และสามารถใช้ภาพมาสคอตที่มีอยู่จริงใน `assets/` อย่างจำกัด หากสไตล์ต้องการ ความชัดของหน้าไม่ควรพึ่งมาสคอต โมทีฟเฉพาะของเนื้อหาคือ “แฟ้มคดี + เส้นทางการเรียน 3 ขั้น + โล่ข้อมูล” ซึ่งสามารถแปลงเป็นเลขคดี, เส้นนำสายตา, เส้นกริด และสัญลักษณ์ตรวจสอบ โดยไม่จำเป็นต้องสร้างภาพใหม่ ห้ามใช้ placeholder ว่างหรือภาพ stock ทั่วไป

## สิ่งส่งมอบสามทิศทาง

แต่ละทิศทางต้องเป็นหน้า HTML ที่ใช้งานและเลื่อนได้จริง ไม่เกิน 1,000 บรรทัด มี anchor navigation, hover/focus state และ responsive layout ใช้เนื้อหาและลิงก์เดียวกันเพื่อให้เปรียบเทียบดีไซน์ได้ยุติธรรม แต่ skeleton ห้ามเหมือนกัน ทิศทาง A ใช้ผล seconds-wheel ลำดับที่ 4: Friendly Geometric Candy ตีความให้สะอาดและมีวินัย ทิศทาง B ยึดหลัก GOV.UK Design System เรื่อง task-first navigation, mobile-first, ความชัดและ focus state แต่ไม่ลอกแบรนด์รัฐบาลอังกฤษ ทิศทาง C ตีความปรัชญา “White” ของ Kenya Hara ให้เป็นพื้นที่ว่างที่ทำหน้าที่สื่อสาร ใช้ความเบา ความละเอียด และกระดาษ/แฟ้มคดีแบบ editorial ทั้งสามเวอร์ชันต้องดูเป็นเว็บไซต์คนละสำนัก ไม่ใช่เปลี่ยนสีบนโครงเดียวกัน
